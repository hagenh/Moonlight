# LAMPLIGHT Codebase Improvement Plan

## Context
Solo-dev Unity 6 prototype (42 scripts, ~3,250 LOC) at Phase 3 of a 6-phase build plan. The code has solid architectural bones (event bus, player FSM, `IInteractable` polymorphism) but has accumulated prototype-stage debt: duplicated code, leftover debug logs, magic numbers, no tests, namespace gaps, and per-frame allocations in hot paths.

This plan addresses both quick cleanup wins and structural improvements, ordered from lowest-risk to highest-risk.

## Phase 2: Code Deduplication (1 new file, 4 modified)

### 2.1 Extract shared PunchScale utility
**New file:** `Assets/Scripts/JuiceUtils.cs`
- Static class with a coroutine method that performs the 3-phase squash-and-stretch:
  ```
  Phase 1 (0.08s): scale to (baseX*0.7, baseY*1.3)
  Phase 2 (0.10s): scale to (baseX*1.15, baseY*0.9)
  Phase 3 (0.10s): scale back to base
  ```
- Signature: `public static IEnumerator PunchScale(Transform target)` — reads `target.localScale` as base, animates, restores. Uses `Mathf.SmoothStep` and `Mathf.Lerp` matching existing behavior.
- Since it's a static coroutine, callers must `StartCoroutine(JuiceUtils.PunchScale(transform))`.

**Modified files:**

## Phase 3: Performance Fixes (3 modified files, 1 event addition)

### 3.1 Throttle FermentManager.Update
**File:** `Assets/Scripts/FermentManager.cs`
- Add field: `private readonly Dictionary<FermentVat, int> _lastProgressPercent = new();`
- In `Update()`, before firing `OnBatchProgressed`:
  ```csharp
  int pct = Mathf.FloorToInt(vat.CurrentBatch.Progress * 100f);
  if (!_lastProgressPercent.TryGetValue(vat, out int last) || last != pct)
  {
      _lastProgressPercent[vat] = pct;
      GameEvents.OnBatchProgressed(vat, vat.CurrentBatch.Progress);
  }
  ```
- When a vat is unregistered, remove it from `_lastProgressPercent`.
- This reduces event firing from ~60/sec to at most ~1/sec per vat (progress changes slowly).

### 3.2 Remove unnecessary FermentVat progress subscription
**File:** `Assets/Scripts/FermentVat.cs`
- Remove `GameEvents.BatchProgressed += OnBatchProgressed;` from `OnEnable()` (line 22)
- Remove `GameEvents.BatchProgressed -= OnBatchProgressed;` from `OnDisable()` (line 30)
- Remove `OnBatchProgressed` method (lines 78-81)
- Rationale: `RefreshVisuals()` sets color based on `State` (Empty/Fermenting/Ready), NOT on progress percentage. The per-frame progress event triggers a no-op color reassignment. Progress is still shown to the player via `GameHUD.UpdateInteractPrompt` (which polls on demand) and `FermentVat.Interact()` (toast on interaction).

### 3.3 Add CashChanged event + make GameHUD event-driven for cash
**Files:**
- `Assets/Scripts/GameEvents.cs` — add:
  ```csharp
  public static event System.Action<int> CashChanged;
  public static void OnCashChanged(int newCash) => CashChanged?.Invoke(newCash);
  ```
- `Assets/Scripts/GameManager.cs` — fire event in `AddCash()` and `TrySpend()`:
  ```csharp
  public void AddCash(int amount) { Cash += amount; GameEvents.OnCashChanged(Cash); }
  public bool TrySpend(int amount) { if (Cash < amount) return false; Cash -= amount; GameEvents.OnCashChanged(Cash); return true; }
  ```
- `Assets/Scripts/UI/GameHUD.cs`:
  - Subscribe to `GameEvents.CashChanged` in `OnEnable`, unsubscribe in `OnDisable`
  - Add `OnCashChanged(int newCash)` handler that updates `cashText.text = $"{newCash}g"`
  - Remove `UpdateCashDisplay()` call from `Update()` (line 68)
  - Call `OnCashChanged(GameManager.Instance.Cash)` in `Awake` for initial display

### 3.4 Cache clock display string
**File:** `Assets/Scripts/UI/GameHUD.cs`
- Add fields: `private int _lastClockHour = -1; private int _lastClockMinute = -1;`
- In `UpdateClockDisplay()`, only rebuild string when values change:
  ```csharp
  private void UpdateClockDisplay()
  {
      if (TimeManager.Instance == null || clockText == null) return;
      int h = TimeManager.Instance.Hour;
      int m = TimeManager.Instance.Minute;
      if (h == _lastClockHour && m == _lastClockMinute) return;
      _lastClockHour = h;
      _lastClockMinute = m;
      clockText.text = $"{h:00}:{m:00}";
  }
  ```
- Note: Clock must stay in `Update()` (minute changes can happen between `HourChanged` events), but the string allocation is now gated.

**Verification:** Play test — verify cash updates when buying/selling, clock updates in real-time, fermentation progress shows correct percentage when interacting with vat. Check Profiler > CPU Usage > GC Alloc to confirm reduced per-frame allocations.

> **Risk: HIGH.** This is the most disruptive change. Do it as a single focused session. Expect compile errors that surface hidden coupling.

Apply `namespace Lamplight.Core` to pure data/logic types:
- `Assets/Scripts/ItemDef.cs`

- `Assets/Scripts/GameEvents.cs`

Apply `namespace Lamplight.Game` to everything else:

- All entities (Building class, FermentVat, Resident, Debris, DebrisPile, SellerInteractable, Bed, DayNightLighting, DevLabel)

Add `using Lamplight.Core;` to every file in `Lamplight.Game`.
Fix the Player/States namespace inconsistency — all states go in `Lamplight.Game` (not `Player.States`), removing the `using Player.States;` from IdleState and MoveState.

### 5.2 Add assembly definition files
Create two `.asmdef` files:

**`Assets/Scripts/Lamplight.Core.asmdef`:**
```json
{
    "name": "Lamplight.Core",
    "rootNamespace": "Lamplight.Core",
    "references": [],
    "includePlatforms": [],
    "excludePlatforms": [],
    "allowUnsafeCode": false,
    "overrideReferences": false,
    "precompiledReferences": [],
    "autoReferenced": true,
    "defineConstraints": [],
    "versionDefines": [],
    "noEngineReferences": false
}
```
Note: `noEngineReferences: false` because `ResidentDef` uses `UnityEngine.Color` and `UnityEngine.Random`, and `FermentBatch` uses `Mathf`.

**`Assets/Scripts/Lamplight.Game.asmdef`:**
```json
{
    "name": "Lamplight.Game",
    "rootNamespace": "Lamplight.Game",
    "references": ["Lamplight.Core"],
    "includePlatforms": [],
    "excludePlatforms": [],
    "allowUnsafeCode": false,
    "overrideReferences": false,
    "precompiledReferences": [],
    "autoReferenced": true,
    "defineConstraints": [],
    "versionDefines": [],
    "noEngineReferences": false
}
```

**Why only two assemblies (not Core/Gameplay/Player/UI):**
There's a circular dependency: Player states reference `Building`/`BuildingManager` (Gameplay), and Gameplay managers reference `PlayerController.Instance` (Player). Splitting these into separate assemblies would require extracting interfaces or refactoring singleton access — too much work for a prototype. A two-assembly split (Core = pure logic, Game = everything else) gives us the test boundary without fighting circular dependencies.

**DebugMenu note:** Since DebugMenu is wrapped in `#if UNITY_EDITOR`, it can stay in the Game assembly. Alternatively, move it to an editor-only assembly, but that's optional.

**Verification:** This will likely surface compile errors from missed `using` statements. Fix iteratively. Run full play test after compilation succeeds.
