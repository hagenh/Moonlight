## GameEvents Implementation Plan

### What GameEvents Is

A static C# event bus. Systems fire events; UI and other systems subscribe. No direct singleton coupling (no more `Building` calling `GameHUD.Instance.ShowToast()`).

### File: `Assets/Scripts/GameEvents.cs`

```csharp
using UnityEngine;

public static class GameEvents
{
    // Fired after a building's state changes
    // (Building that changed, old state, new state)
    public static event System.Action<Building, BuildingState, BuildingState> BuildingStateChanged;

    // Fired when a fragment is discovered
    public static event System.Action<Fragment> FragmentFound;

    // Fired when a resident moves into a building
    public static event System.Action<Resident, Building> ResidentMovedIn;

    // Fired when the day ends (before tick processing)
    public static event System.Action<int> DayEnded;

    // Fired when heat value changes
    // (new heat, old heat)
    public static event System.Action<int, int> HeatChanged;

    // Fired when reputation value changes
    // (new rep, old rep)
    public static event System.Action<int, int> RepChanged;

    // Convenience fire methods — one-liners so callers don't need null checks
    public static void OnBuildingStateChanged(Building b, BuildingState oldState, BuildingState newState)
        => BuildingStateChanged?.Invoke(b, oldState, newState);

    public static void OnFragmentFound(Fragment f)
        => FragmentFound?.Invoke(f);

    public static void OnResidentMovedIn(Resident r, Building b)
        => ResidentMovedIn?.Invoke(r, b);

    public static void OnDayEnded(int day)
        => DayEnded?.Invoke(day);

    public static void OnHeatChanged(int newHeat, int oldHeat)
        => HeatChanged?.Invoke(newHeat, oldHeat);

    public static void OnRepChanged(int newRep, int oldRep)
        => RepChanged?.Invoke(newRep, oldRep);
}
```

### Who Fires What

| Event | Fired By | When |
|-------|----------|------|
| `BuildingStateChanged` | `Building.cs` | After `State` changes (purchase, repair) |
| `DayEnded` | `GameManager.cs` | In `AdvanceDay()`, before income ticks |
| `HeatChanged` | `GameManager.cs` | When heat changes (no callers yet — stub) |
| `RepChanged` | `GameManager.cs` | When rep changes (no callers yet — stub) |
| `FragmentFound` | *(future)* | When player finds a fragment |
| `ResidentMovedIn` | *(future)* | When NPC moves in |

### Who Subscribes To What

| Event | Subscriber | Reaction |
|-------|-----------|----------|
| `BuildingStateChanged` | `GameHUD` | Show toast (replaces direct `ShowToast` call from Building) |
| `BuildingStateChanged` | `Building` (self) | Toggle Light2D / dev label when own state changes |
| `DayEnded` | `GameHUD` | Update day display |
| `DayEnded` | `Building`s | Accumulate daily income |
| `HeatChanged` | `GameHUD` | Update heat display (future) |
| `RepChanged` | `GameHUD` | Update rep display (future) |

### Refactoring Changes

**`Building.cs`:**
- In `TryPurchase()` and `TryRepair()`: fire `GameEvents.OnBuildingStateChanged(this, oldState, newState)` after state change
- Remove `ShowToast()` — HUD subscribes to `BuildingStateChanged` and shows its own toast
- `AccumulateDailyIncome()` — subscribe to `DayEnded` instead of being called by `GameManager` via `FindObjectsByType`
- Subscribes/unsubscribes in `OnEnable`/`OnDisable`

**`GameManager.cs`:**
- Expand with `Heat`, `Reputation` properties that fire `HeatChanged`/`RepChanged` on change
- `AdvanceDay()`: fire `GameEvents.OnDayEnded(Day)` instead of `FindObjectsByType<Building>` loop
- `TrySpend()` / `AddCash()`: no event needed yet (HUD can subscribe to a future `CashChanged` event if polling becomes an issue)

**`GameHUD.cs`:**
- Subscribe to `GameEvents.BuildingStateChanged` → show toast
- Subscribe to `GameEvents.DayEnded` → update day text
- `UpdateInteractPrompt()` stays in Update (it depends on player position, not events)
- `UpdateCashAndDay()` stays in Update for now (cash has no event yet — can add `CashChanged` later)
- Remove the `Instance` singleton pattern for toast — Building no longer calls it directly

### Execution Order

1. Create `GameEvents.cs`
2. Expand `GameManager.cs` with Heat/Rep + fire DayEnded
3. Refactor `Building.cs` — fire BuildingStateChanged, subscribe to DayEnded, remove ShowToast
4. Refactor `GameHUD.cs` — subscribe to BuildingStateChanged for toasts, subscribe to DayEnded for day display
5. Play-test: buy a building, see toast via event; advance day, see income accumulate via event
