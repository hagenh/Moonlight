# Phase 2a: Fermentation + Inventory

## Goal
Build the inventory system, game-hour clock, and fermentation pipeline so that the player can: acquire ingredients → start a batch in a vat → watch it ferment by game-hours → collect bottles. This is the foundation that the still minigame and selling channels will plug into later.

## BuildPlan reference
Phase 2 line: *"Ferment: batches tick with game hours. Vat interactable: empty → choose recipe (consume ingredients) → fermenting → ready → minigame. Second vat purchasable mid-slice."*

## Implementation order

### Step 1: Data types (no dependencies)
1. `ItemType.cs` — `enum ItemType { Grain, Sugar, Yeast, Water, Bottle }`
2. `VatState.cs` — `enum VatState { Locked, Empty, Fermenting, Ready }`
3. `RecipeData.cs` — serializable class with parallel `List<ItemType>` + `List<int>` for ingredient costs (Unity can't serialize Dictionary), lazy-built `IReadOnlyDictionary` accessor
4. `FermentBatch.cs` — tracks `RecipeData`, `hoursElapsed`, `totalHours`; `Progress` (0..1), `IsComplete`, `TickHour()`

### Step 2: GameEvents + InteractType
- `GameEvents.cs`: add 5 new events + invokers:
  - `HourChanged(int hour, int day)` — fired by TimeManager each game-hour
  - `InventoryChanged(ItemType type, int oldCount, int newCount)` — fired by InventoryManager
  - `VatStateChanged(FermentVat vat, VatState oldState, VatState newState)` — fired by FermentManager
  - `BatchProgressed(FermentVat vat, float progress)` — fired by FermentManager on hour tick
  - `RecipeSelectionRequested(FermentVat vat)` — fired by FermentVat.Interact when Empty
- `IInteractable.cs`: add `FermentVat` to `InteractType` enum

### Step 3: TimeManager (new)
- Singleton MonoBehaviour
- Configurable `realSecondsPerGameMinute` (default ~0.77 for ~15-min day)
- Tracks `Day` (starts 1), `Hour` (starts 6), `Minute`, fractional accumulator
- `Update()`: accumulate real time → increment game-minutes → on hour boundary fire `OnHourChanged(hour, day)`
- Auto-advance day when hour reaches `dayEndHour` (22): fire `OnDayEnded(Day)`, increment Day, reset to `dayStartHour` (6)
- `AdvanceHour()` for debug; `AdvanceToDayEnd()` for sleep

### Step 4: GameManager refactor
- Remove `Day` property and `AdvanceDay()` method (now in TimeManager)
- Keep: Cash, Heat, Reputation, TrySpend, AddCash, SetHeat, SetReputation
- All existing `DayEnded` subscribers continue working unchanged (event signature same, now fired by TimeManager)

### Step 5: InventoryManager (new)
- Singleton MonoBehaviour
- `Dictionary<ItemType, int>` storage
- `TryAdd(type, count)` → mutate + fire `OnInventoryChanged` + toast
- `TryRemove(type, count)` → validate + mutate + fire event + toast on failure
- `Has(type, count)` → check only
- `GetCount(type)` → read

### Step 6: FermentManager (new)
- Singleton MonoBehaviour
- `[SerializeField] RecipeData[] recipes` (2 recipes: Basic Mash, Sweet Batch)
- `[SerializeField] int secondVatCost = 200`
- Register/Unregister vats (same pattern as BuildingManager)
- Subscribe to `HourChanged`: for each fermenting vat, call `batch.TickHour()`, fire `OnBatchProgressed`, check `IsComplete` → `MarkReady` + fire `OnVatStateChanged`
- `TryStartBatch(vat, recipe)`: validate Empty state + ingredients → consume from inventory → create batch → set vat to Fermenting → fire event + toast
- `TryCollectBatch(vat)`: validate Ready → add bottles to inventory → clear vat to Empty → fire event + toast. **This is the handoff point for the still minigame (v1: direct collect; v2: launch still scene)**
- `TryPurchaseSecondVat(vat)`: validate Locked + can afford → spend cash → set vat to Empty → fire event + toast

Starting recipes:

| Recipe | Ingredients | Hours | Bottles |
|--------|------------|-------|---------|
| Basic Mash | Grain×2, Water×1, Yeast×1 | 4 | 3 |
| Sweet Batch | Grain×1, Sugar×2, Yeast×1, Water×1 | 6 | 4 |

### Step 7: FermentVat (new)
- MonoBehaviour + IInteractable
- `vatIndex` (0=primary, 1=second), `purchaseCost` (only meaningful for index 1)
- State starts as Empty (index 0) or Locked (index 1)
- `Interact()` routes by state:
  - Locked → `FermentManager.TryPurchaseSecondVat(this)`
  - Empty → fire `OnRecipeSelectionRequested(this)`
  - Fermenting → toast progress %
  - Ready → `FermentManager.TryCollectBatch(this)`
- `SetBatch(batch)` → Fermenting + visuals
- `MarkReady()` → Ready + visuals + PunchScale (same coroutine as Building.cs)
- `ClearBatch()` → Empty + visuals
- `RefreshVisuals()`: vat color grey/blue/green by state
- Subscribe to `VatStateChanged` + `BatchProgressed` for self-reacting visual updates (same pattern as Building)

### Step 8: RecipeSelectUI (new)
- IMGUI popup (same pattern as DebugMenu)
- Subscribes to `RecipeSelectionRequested`: shows modal window with recipe buttons
- Each button shows: recipe name, ingredients (with inventory counts), ferment time, output
- Buttons disabled if ingredients missing
- On click → `FermentManager.TryStartBatch(vat, recipe)` → close on success

### Step 9: Update existing files
- **GameHUD.cs**: add `[SerializeField]` fields for heatText, repText, clockText; subscribe to HourChanged/HeatChanged/RepChanged; add `else if (interactable is FermentVat vat)` branch in `UpdateInteractPrompt` with state-specific text; update Day display to read from TimeManager
- **DebugMenu.cs**: update `GameManager.Instance.Day` → `TimeManager.Instance.Day`, `GameManager.Instance.AdvanceDay()` → `TimeManager.Instance.AdvanceToDayEnd()`; add ingredient grant buttons (Grain/Sugar/Yeast/Water +5 each), advance-hour button, skip-fermentation button, inventory stock display

## Key design decisions

| Decision | Rationale |
|----------|-----------|
| `VatState.Locked` for second vat | Same IInteractable pattern, no extra GameObjects. Vat 0 starts Empty, Vat 1 starts Locked. |
| Recipe selection via IMGUI | Matches DebugMenu pattern. Zero art setup. Replace in Phase 5. |
| Dictionary<ItemType,int> for inventory | O(1) lookup, simple. Only ~5 item types — no slot grid needed. |
| Day moved from GameManager to TimeManager | Day semantically belongs with time. GameManager keeps wallet+stats only. |
| V1 batch collect = direct bottles-to-inventory | Placeholder for still minigame. Clean swap point — only `Ready` state's Interact handler changes. |
| No intermediate Mash item type | Recipe consumes raw ingredients directly. Mash step can be added later without restructuring. |
| Parallel lists for RecipeData costs | Unity can't serialize Dictionary. Runtime dict built lazily on accessor. Matches "serialized fields over ScriptableObjects" convention. |

## Still minigame handoff (future)

When the still minigame is built, `FermentVat.Interact()` in `Ready` state changes from `FermentManager.TryCollectBatch(this)` to `FermentManager.LaunchStillMinigame(this)`. The still scene returns quality (1-5★) via event. `FermentManager` calculates output and adds bottles. No structural changes to FermentVat, FermentBatch, or InventoryManager.
