# Narrative System Redesign Plan

## Vision
Replace "fragments only from smashing debris" with a blended narrative system: NPC relationships, milestone triggers, and collectible fragments — all sources feed into a journal and drive dialogue progression.

## Design Principle
**Design full system, implement only what's needed for the current slice** (5 fragments, Berta + upcoming NPCs, Bakery arc).

## New Systems to Add

### 1. NarrativeFlags — Global boolean state tracker
**New file:** `Assets/Scripts/NarrativeFlags.cs`
- Static class: `HashSet<string>` of set flags
- `IsSet(flag)`, `Set(flag)`, `Clear(flag)`, `AllFlags`
- `Set()` fires `GameEvents.OnFlagSet(flag)` — lets other systems react
- Flags like: `bakery_restored`, `first_sale`, `berta_moved_in`, `bakery_fragment_found`
- Serializable for future save/load

### 2. MilestoneDetector — Bridge from game events to flags
**New file:** `Assets/Scripts/MilestoneDetector.cs`
- MonoBehaviour, subscribes to existing GameEvents
- Sets flags on first-time events:
  - `BuildingStateChanged` → `bakery_restored`, `four_buildings_restored`
  - `InventoryChanged` (bottle gained) → `first_batch_produced`
  - `ResidentMovedIn` → `berta_moved_in`, etc.
  - `SleepCompleted` → day-based flags
- Follows existing pattern: event subscriber like BuildingManager/SellManager

### 3. FragmentDef — Story fragment data
**New file:** `Assets/Scripts/FragmentDef.cs`
- Plain C# class (follows ItemDef/ResidentDef pattern): id, title, body (~120 words), triggerType enum, sourceId
- `triggerType`: `SmashDebris` (from renovation), `Milestone` (from flag), `NPCGift` (from dialogue)
- This replaces the BuildPlan's "one scripted debris per fragment building" with a broader model
- Register 5 fragments in `ContentDb`

### 4. Fragment discovery — Trigger logic
**Modify:** `Assets/Scripts/BuildingManager.cs`
- When `TrySmashHit` completes board-smashing on a fragment building, fire `GameEvents.OnFragmentFound(fragmentDef)` instead of normal debris for that piece
- Also: `MilestoneDetector` fires `OnFragmentFound` for milestone-triggered fragments when the matching flag is set
- Also: NPC dialogue can set a flag that triggers a fragment (NPCGift type)

### 5. FragmentUI — Letter overlay
**New file:** `Assets/Scripts/UI/FragmentUI.cs`
- OnGUI overlay (same pattern as DialogueUI): faded parchment background, title, body text
- Dismissed by E/Escape
- Subscribes to `FragmentFound` event
- On close: adds fragment to journal, sets `NarrativeFlags.Set($"{fragmentId}_found")`

### 6. JournalState — Collected fragments + milestones
**New file:** `Assets/Scripts/JournalState.cs`
- Static or singleton: `List<FragmentDef>` collected, `List<string>` milestone log
- `AddFragment()`, `AddMilestone()`
- Subscribes to `FragmentFound` and `FlagSet`
- No UI yet (journal viewer is a later task — just the data layer)

### 7. Per-NPC trust — Upgrade ResidentDef/ResidentManager
**Modify:** `Assets/Scripts/ResidentDef.cs`
- Add `DialogueLine[] conditionalLines` — priority-sorted list of lines with conditions
- New `DialogueLine` struct: text, requiredFlag, setsFlag, minTrust, oneShot

**New file:** `Assets/Scripts/DialogueLine.cs`
- Serializable struct: text, requiredFlag, setsFlag, minTrust, oneShot, portraitEmotion

**Modify:** `Assets/Scripts/Resident.cs`
- Add `int Trust` property, `HashSet<string> SeenLines`
- `Interact()` uses `DialogueResolver` instead of raw `GetDialogueLine()`

**New file:** `Assets/Scripts/DialogueResolver.cs`
- Static resolver: checks conditional lines in priority order, falls back to rep-tier pool
- On display: if oneShot, add to SeenLines; if setsFlag, set in NarrativeFlags
- Increments NPC trust on each dialogue (+1)

### 8. GameEvents additions
**Modify:** `Assets/Scripts/GameEvents.cs`
- `FlagSet(string flag)` — when any narrative flag is set
- `FragmentCollected(FragmentDef)` — type-safe version of FragmentFound
- `MilestoneReached(string milestone)` — when a milestone is detected

### 9. ContentDb — Register fragments + upgrade Berta
**Modify:** `Assets/Scripts/ContentDb.cs`
- Add `Dictionary<string, FragmentDef> Fragments`
- Add 5 static FragmentDef fields ( Bakery fragment from smash, Mill fragment from milestone, etc.)
- Add `DialogueLine[] conditionalLines` to Berta (e.g., one-shot move-in greeting)

## Implementation Order
1. NarrativeFlags + GameEvents additions (foundation)
2. FragmentDef + ContentDb registration
3. MilestoneDetector
4. Fragment discovery in BuildingManager smash pipeline
5. FragmentUI + JournalState
6. DialogueLine struct + DialogueResolver
7. ResidentDef upgrade + Resident trust
8. Berta conditional lines

## What NOT to Build (deferred)
- No quest log UI (BuildPlan explicitly excludes)
- No dialogue node editor or visual tool
- No branching dialogue with player choices
- No journal viewer UI (data layer only for now)
- No cutscene framework (keep using coroutines)
- No save/load integration yet (flags are in-memory)
